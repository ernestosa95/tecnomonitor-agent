Integridad de bases (directo a SQL)

Ejecuta DBCC CHECKDB sobre las bases solo cuando SQL Server se reinicia (típicamente por un corte de energía) y manda el resultado una vez. Es una tarea larga: corre en un proceso aparte y no frena el resto de las mediciones. Es la excepción: si el hospital tiene Elastic, usar "Integridad de bases" en la tarjeta de Elastic. Si ambas están activas, gana la de Elastic. Usa la misma conexión SQL configurada arriba, y ese usuario necesita ser sysadmin o db_owner de cada base.

Completo = como la consulta manual. El liviano es mucho más rápido pero no detecta problemas lógicos.

Integridad de bases (CHECKDB, vía Elastic)

Lee el resultado del DBCC CHECKDB que Logstash ejecuta cuando SQL Server se reinicia (pipeline ext_checkdb, ver la carpeta elk/) y lo manda una sola vez por reinicio. El tipo de chequeo (completo o liviano) y la lista de bases se editan en ext_checkdb.conf (bloque CONFIGURACIÓN del statement) del servidor ELK, no acá. Requiere permiso de lectura sobre ese índice para el usuario configurado en la tarjeta de Elastic.

Un documento por base y por reinicio (no se pisa el historial).
